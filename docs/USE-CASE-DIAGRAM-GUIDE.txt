================================================================================
                    1. PROJECT OVERVIEW
================================================================================

Project Type: E-Commerce Platform with Service-Oriented Architecture
Main Purpose: Online shopping platform with product catalog, shopping cart,
              order management, and administrative functions

Key Features:
- Product browsing and search
- Shopping cart management
- User authentication and authorization
- Order placement and tracking
- Product reviews
- Loyalty points system
- Admin management console
- OAuth social login (Google, Facebook)
- Discount code system

================================================================================
                    2. ACTORS IDENTIFICATION
================================================================================

PRIMARY ACTORS (Human Users):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Guest User
   - Description: Anonymous visitor to the website
   - Capabilities: Browse products, view details, guest checkout
   - Authentication: None required

2. Registered User (Customer)
   - Description: Authenticated user with an account
   - Capabilities: All guest capabilities + account management, order history,
                   saved addresses, loyalty points
   - Authentication: Email/password or OAuth (Google/Facebook)

3. Administrator
   - Description: Staff member with administrative privileges
   - Capabilities: Manage products, orders, users, discounts, view analytics
   - Authentication: Email/password with admin role
   - Inherits: Registered User capabilities

SECONDARY ACTORS (External Systems):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

4. Payment Gateway
   - Description: External payment processing system
   - Interaction: Process payments for orders

5. Email Service
   - Description: Email notification system (Gmail SMTP)
   - Interaction: Send registration confirmations, order updates, password reset

6. OAuth Providers
   - Description: Google and Facebook authentication services
   - Interaction: Authenticate users via OAuth 2.0

7. Database System
   - Description: MongoDB database
   - Interaction: Store and retrieve data

================================================================================
            7. RELATIONSHIPS AND EXTENSIONS
================================================================================

GENERALIZATION (Inheritance):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Registered User extends Guest User
  → Inherits all guest capabilities
  → Adds authentication-required features

- Administrator extends Registered User
  → Inherits all user capabilities
  → Adds administrative functions

Notation: Draw with hollow triangle arrow pointing to parent actor

INCLUDE RELATIONSHIPS:
━━━━━━━━━━━━━━━━━━━━━━
Use <<include>> when a use case ALWAYS uses another use case.

Examples:
- "Place Order" <<includes>> "Verify Discount Code"
- "Manage Shopping Cart" <<includes>> "Update Inventory"
- "Register Account" <<includes>> "Send Email Notification"
- "View Product Details" <<includes>> "View Product Images"

Notation: Dashed arrow with <<include>> label, pointing from base use case
         to included use case

EXTEND RELATIONSHIPS:
━━━━━━━━━━━━━━━━━━━━━
Use <<extend>> when a use case OPTIONALLY enhances another.

Examples:
- "Apply Loyalty Points" <<extends>> "Place Order"
